Write the style inside the class name.

Laibery reads class tokens such as b$2$s$red and generates real CSS at runtime. This page is the complete route: every curated alias, all 520 CSS properties, values, variants, theming, override behavior and the JavaScript API.

Browse all 520 classes Open the live demo

How it works

1. Load one file

Add <script src="laibery.js"></script>. It auto-starts and observes new elements. No build, no separate stylesheet.

2. Write a class

b$2$s$red means border 2px solid red. p$16 means padding 16px. Classes without $ are ignored.

3. It wins by default

Declarations carry !important and the generated sheet stays last, so normal CSS a site wrote earlier loses.

Minimal page
<script src="/laibery.js"></script>

<div class="b$2$s$red p$16 r$8 bg$surface">
  Hello, Laibery
</div>

Use on any website

You only need one JavaScript file. It works on a page you control, a CMS page, a tiny HTML widget, or a site where you inject a script later.

Host the file

Put laibery.js next to the HTML, on GitHub Pages, S3, a CDN, or any static host.

<script src="https://your-host.example/laibery.js"></script>

Or add it before </body>

The library scans the existing DOM and watches for future elements with a MutationObserver.

<script src="/laibery.js"></script>

CSP and nonces

If style-src does not allow 'unsafe-inline', give the generated style element the page's nonce before Laibery loads.

<script nonce="abc123">
  window.__LAIBERY_CONFIG__ = { nonce: 'abc123' };
</script>
<script nonce="abc123" src="/laibery.js"></script>

The script tag also needs a nonce when script-src requires one. You can also call Laibery.config({ nonce: 'abc123' }) before the first scan.

Verify it loaded

Laibery.version;                         // "0.2.0"
document.getElementById('laibery-styles'); // generated style element
Laibery.preview('b$2$s$red');            // CSS string, or null

If Laibery is undefined, the script URL is wrong, the request was blocked, or the file was not served as JavaScript. If the style element is missing, call Laibery.start() or check the console.

Override earlier site CSS

This is the behavior that makes Laibery useful on pages you do not own. Suppose the site already wrote: 

<style>
  .card { border: 1px dashed #94a3b8; background: #ffe4e6; }
</style>

<div class="card">Site styling</div>

Add Laibery classes to the same element:

<div class="card b$3$s$primary bg$surface">
  Laibery styling
</div>

Laibery generates:

[class~="b$3$s$primary"] {
  border-width: 3px !important;
  border-style: solid !important;
  border-color: var(--lb-primary) !important;
}
[class~="bg$surface"] {
  background-color: var(--lb-surface) !important;
}

The generated declarations beat the site's normal .card declarations even though both selectors have class-level specificity. Laibery also keeps its <style id="laibery-styles"> after the site's own styles, so at equal specificity its !important wins on document order.

Important caveat: a site !important rule with higher specificity (for example #app .card) still wins, and a site inline style="... !important" still wins. Most normal site CSS is overridden; these edge cases are not.

What the runtime does

  1. Appends the generated stylesheet at the end of <body> (or head/html if there is no body).
  2. Watches for new <style> and <link> elements and moves the Laibery sheet after them.
  3. Recreates the sheet if a script or framework removes it.
  4. Reuses the same <style id="laibery-styles"> element instead of creating one per update.

Disable !important with Laibery.config({ important: false }). The sheet still stays last, so same-specificity ties still favor Laibery; higher-specificity site rules win.

Configuration

Laibery.config();                        // { important: true, nonce: '' }
Laibery.config({ important: false });   // opt out of !important
Laibery.config({ nonce: 'abc123' });    // CSP nonce

// Before the library loads:
window.__LAIBERY_CONFIG__ = { important: true, nonce: 'abc123' };

Manual start and custom properties

// Disable auto-start before loading:
window.__LAIBERY_MANUAL__ = true;
Laibery.start();

// Pre-generate rules:
Laibery.add('p$24 b$2$s$primary md:cols$3');

// Add a custom property:
Laibery.define('trbl', 200, function (values) {
  return [['transform', 'translate(' + values[0] + 'px,' + values[1] + 'px)']];
});
// <div class="trbl$10$20">

define is JavaScript you write. Validate any untrusted value before returning it as CSS.

For AI and other tools

These files are generated from the same source map as the library, so an AI or coding tool can read them and work on another website without guessing class names.

classes.json

Structured data: syntax, config, variants, values, curated aliases, 520 properties and examples in JSON.

llms.txt

Short LLM index: install, critical rules, conflicts and links to the full reference.

llms-full.txt

Full Markdown guide plus the complete 520-property table, ready to paste into an AI context.

aliases.md

Human-readable Markdown property reference with aliases, examples and conflicts.

AI handoff: read classes.json and llms-full.txt. Use only documented aliases or full property names; every token must contain $; prefer full property names when unsure; do not use d/r for SVG (use svg-d/svg-r); Laibery's generated declarations use !important by default.

Limitations

  • Values cannot contain spaces. Use aliases or functions without spaces (calc(100%/3) works; calc(100% - 3px) does not).
  • Runtime only: there is no static extraction, SSR stylesheet or build-time purging.
  • JavaScript is required; the page has no styles until Laibery runs.
  • No automatic vendor prefixing.
  • Override relies on !important plus stylesheet order. A site inline style with !important still wins; a site !important rule with higher specificity also wins.
  • Strict CSP needs a nonce.
  • Shadow DOM is not scanned; only the main document is observed.
  • Rules accumulate until reload; there is no automatic cleanup for tokens no longer in the DOM.
  • dark: is class-based (.dark ancestor), not prefers-color-scheme.
  • Variants cover pseudo-classes, breakpoints and dark:; there are no @supports or container-query variants yet.
